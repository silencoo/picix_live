# Picix 脚本整理与 Bot 优化方案

## 目标

1. 网络故障、认证失效和真实空数据必须严格区分。
2. 自动购买必须 `fail closed`：任何关键状态不确定时都不扣积分。
3. Telegram 交互应少刷屏、不阻塞，并明确告诉用户当前动作与停止原因。
4. 在保持现有命令兼容的前提下，逐步拆分根目录的大型脚本。

## 线上核查结论（2026-08-13）

- 初次核查时 Bot 由 `python -m picix_bot` 运行；模块拆分后统一入口为
  `uv run --locked --env-file .env picix bot`。
- `/Packages/listMine` 当前返回 1 个有效包：`total=30`、`used=5`，即剩余 25 次。
- `/Malls/listGoods` 返回 3 个资源包、2 个邀请码和 2 个兑换码。
- 商城资源包使用字段 `id/name/desc/price/validDays`；次数没有独立字段，只出现在
  `desc`，例如 `30次包，可解锁30个资源`。
- 日志中出现过 401 和 Cloudflare 522。旧代码把这些失败响应继续折叠成 `[]`，上层因而可能把
  “状态读取失败”理解为“额度为 0”或“没有商品”。

## 安全不变量

- 只有资源包接口明确成功且返回合法列表时，才允许计算剩余额度。
- 只有任务、积分、资源包和商城状态全部可用时，才允许自动购买。
- 购买前重新读取商城并校验商品 ID、价格和次数。
- 购买后重新读取个人资源包；无法确认额度到账时不得继续解锁。
- 401/403 触发重新认证；超时、429、5xx 和 522 视为临时故障，不视为退出登录或零额度。
- 同一 Bot 进程内购买、手动优化和定时优化互斥，避免重复点击造成重复扣分。

## 实施阶段

### 第一阶段：线上安全补丁

- [x] API 请求增加超时和结构化失败标记。
- [x] 为任务、积分、资源包、商城增加带 `available/error/auth_failed/retryable` 的状态读取。
- [x] 修复商城分类展开和从商品说明安全解析额度。
- [x] 自动优化、每日解锁和批量解锁在状态不确定时停止。
- [x] 商城购买前重新确认商品存在。
- [x] 定时资源包检查不再把接口故障通知成 0 次。
- [x] 已购影片分页故障不再当作空列表，避免重复解锁或重复购买。
- [x] 关键 Bot 请求移到工作线程，进度消息改为原地更新。
- [x] 购买、批量解锁、手动解锁和定时优化使用同一互斥锁。
- [x] 增加商城真实结构、401、522 和禁止误购的回归测试。

### 第二阶段：模块拆分

目标结构：

```text
picix_bot/
├── api/
│   ├── client.py       # HTTP、超时、错误分类、日志脱敏
│   ├── models.py       # ApiResult 与领域状态
│   └── endpoints.py    # Picix endpoint 封装
├── services/
│   ├── catalog.py      # 商城标准化与购买校验
│   ├── packages.py     # 额度汇总
│   ├── tasks.py        # 任务状态
│   └── unlock.py       # 选片与解锁流程
├── app.py              # Telegram handlers 与定时任务（下一阶段继续拆分）
├── cli.py              # 统一命令入口
└── optimizer.py        # 保持纯计算
```

`auto_unlock_helper.py` 已缩减为兼容导出层；Bot 和 CLI 已改用拆分后的模块。
为降低线上回归风险，本次没有一次性拆散 Telegram handler；后续可按
`messages/handlers/jobs` 逐块迁移，每一块单独回归。

### 第三阶段：脚本入口整理

- [x] `start.sh` 和 `start.bat` 继续作为跨平台控制中心。
- [x] 增加 Python console script，统一为 `uv run picix <command>`。
- [x] `bot/status/unlock.sh|bat` 先保留兼容，至少经过一个发布周期后再删除。
- [x] `tools/` 只放部署和浏览器辅助工具；一次性诊断脚本移到 `scripts/diagnostics/`。
- [x] README 使用统一 `picix <command>` 主流程，其他说明同步入口。

### 第四阶段：部署与观察

1. 本地单元测试和语法检查通过。
2. 在服务器仅执行只读 smoke test，验证任务、积分、额度和商城标准化结果。
3. 更新代码并重启单一 Bot 进程。
4. 手动验证 `/status`、`/package`、`/shop` 和 `/plan`。
5. 不触发真实购买地验证 `/optimize` 计划；观察至少一轮认证检查和资源包检查。
6. 确认稳定后再开启或保留自动购买。
